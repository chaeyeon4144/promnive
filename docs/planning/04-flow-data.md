# 사용자 흐름과 데이터 모양

- 작성일: 2026-11-25
- 단계: P1 기획 — 사용자 흐름(flow) + 데이터 모양
- 이전 문서: [MVP 범위와 IA](03-mvp-ia.md)

> IA가 "방과 복도 지도"였다면, 사용자 흐름은 "한 사람이 그 지도 위를 실제로 걷는 순서"다.
> 데이터 모양은 "각 방에 무엇이 놓이는지"를 정한다. 실제 프롬프트 30개를 채우는 일(데이터 내용)은 S3 개발 때 한다.

## 데이터 모양을 정한 기준

1. **칸 하나마다 그 칸을 쓰는 화면이나 사용자 이야기가 있어야 한다.** 없으면 뺀다.
2. **다른 칸으로 계산할 수 있으면 저장하지 않는다.**
3. **모든 프롬프트가 같은 칸을 가진다.** 없는 값은 칸을 빼지 않고 `null` 또는 `[]`로 둔다.

## 프롬프트 하나의 모양

프롬프트 하나 = 객체 하나. 30개는 배열 하나에 담는다.

```js
const prompt = {
  id: 1,
  title: "생일 포스터 레드 컨셉",
  summary: "내 셀카 한 장으로 선명한 레드 배경의 생일 포스터를 만들어요",
  promptText: `첨부한 사진 속 인물의 얼굴, 헤어스타일, 이목구비를 그대로 유지해 줘.
이 인물로 세로형(9:16) 생일 포스터를 만들어 줘.

- 배경: 선명하고 진한 빨간색 단색 배경
- 조명: 카메라 직광 플래시로 찍은 듯한 또렷한 조명, 피부는 자연스럽게
- 포즈: 생크림 딸기 케이크를 한 손으로 들고 카메라를 바라보며 살짝 웃는 상반신
- 소품: 머리에 작은 빨간 리본
- 글씨: 포스터 위쪽에 흰색 손글씨로 "HAPPY BIRTHDAY {name}"
- 분위기: 생일 매거진 표지처럼 세련되고 사랑스럽게

사진처럼 사실적으로 만들고, 인물의 얼굴은 바꾸지 마.`,
  images: ["/images/1-1.jpg", "/images/1-2.jpg"],
  beforeImage: "/images/1-before.jpg",
  topic: "셀피",
  ai: "ChatGPT",
  needsPhoto: true,
  creator: { name: "도라", instagram: "https://instagram.com/..." },
  blanks: [
    { name: "name", label: "포스터에 넣을 이름 (영어)", example: "MINJI" },
  ],
};
```

| 칸 | 값 종류 | 쓰는 곳 |
|---|---|---|
| `id` | 숫자 | 상세 주소, 보관함 저장. 제목은 겹칠 수 있지만 id는 겹치지 않는다 |
| `title` | 글자 | 카드, 상세, 보관함 |
| `summary` | 글자 | 카드와 상세의 한 줄 설명 |
| `promptText` | 글자 | **복사되는 글**. 빈칸 자리는 `{name 값}`으로 표시 |
| `images` | 글자 배열 | 결과 예시 (사용자 이야기 A-1). 첫 장이 카드 대표 이미지 |
| `beforeImage` | 글자 또는 `null` | 사진이 필요한 프롬프트의 원래 사진. 결과와 나란히 보여 준다 |
| `topic` | 글자 | 홈 주제 칩 필터, 보관함 폴더, 관련 프롬프트 |
| `ai` | 글자 | 이용 방법, AI로 바로가기 |
| `needsPhoto` | `true` / `false` | 이용 방법에 "AI 채팅창에 사진 첨부" 단계를 넣을지 |
| `creator` | 객체 `{ name, instagram }` | 출처 표시 (P0 원칙). 크리에이터는 따로 하나의 대상이라 객체로 묶는다 |
| `blanks` | 객체 배열 | 빈칸 채우기 (사용자 이야기 A-3). 없으면 `[]` |

### 빈칸 (`blanks`)

빈칸 객체 하나 = 화면의 입력칸 하나.

```js
blanks: [
  { name: "name",  label: "이름",     example: "민지" },
  { name: "birth", label: "생년월일", example: "1998-03-15" },
]
```

| 칸 | 뜻 | 화면에서 |
|---|---|---|
| `name` | 코드가 쓰는 이름표 | `<input name="birth">` → 입력할 때 `e.target.name`으로 읽힌다 |
| `label` | 사용자가 보는 이름 | 입력칸 위의 글자 |
| `example` | 예시 | 입력칸 안의 회색 힌트 (`placeholder`) |

- 프롬프트마다 빈칸의 **개수와 내용은 다르지만 모양은 같다.** 그래서 화면은 배열을 돌며 있는 만큼만 입력칸을 그린다.
- `promptText` 속 구멍은 **`label`이 아니라 `name`으로** 표시한다 (`{birth}`). label은 화면 글자라 바뀔 수 있고, name은 바뀌지 않는다. 연결은 바뀌지 않는 쪽으로 한다.
- 1단계 입력칸은 **글자 입력 한 종류**만 둔다. 고르는 버튼형 빈칸이 필요해지면 빈칸 객체에 `type` 칸을 추가한다.

### 일부러 넣지 않은 칸

| 정보 | 이유 |
|---|---|
| 난이도, 걸리는 시간 | 쓰는 화면이나 사용자 이야기가 없다. 복사 → 붙여넣기는 모두 쉽다 |
| 복사·공유·저장 버튼 | 정보가 아니라 동작이다. 화면(컴포넌트)이 맡는다 |
| 관련 프롬프트 | 같은 `topic`인 프롬프트를 찾으면 된다 |
| 이용 방법 문장 | `ai` + `needsPhoto`로 정해진다. 프롬프트마다 쓰면 30번 반복된다 |
| AI 사이트 주소 | `ai` 이름으로 정해진다. AI 목록 한 곳에 한 번만 적는다 |
| 사진 (빈칸으로) | 사진은 우리 사이트가 받지 않고 사용자가 AI 채팅창에 직접 첨부한다. 복사되는 글도 바뀌지 않는다 |

### 결정

| 결정 | 이유 | 포기한 것 |
|---|---|---|
| 결과는 모두 이미지(캡처)로 통일 | 결과 종류가 두 개면 화면도 두 종류가 된다. 사주처럼 글로 나오는 결과도 AI 화면을 캡처한다 | 결과 글을 그대로 보여 주기 |
| before/after는 1단계에 **두 장 나란히** | 데이터(`beforeImage`)만 있으면 화면은 나중에 바꿀 수 있다 | 가운데를 끌어서 비교하는 슬라이더 (나중) |
| 인기 TOP은 프롬프트 칸이 아니라 홈 쪽에 id 목록으로 | 인기는 프롬프트의 정보가 아니라 홈 화면의 편집 결정이다 | `isPopular` 같은 칸 |

## 이 기기에만 저장 (localStorage)

**저장한 프롬프트의 `id`만** 배열로 기억한다.

```js
// localStorage에 저장되는 값
[3, 1, 7]
```

| | 내용 |
|---|---|
| 이유 | 프롬프트 내용은 우리 데이터에 있다. 운영자가 제목이나 이미지를 고치면, id만 저장한 보관함에도 고친 내용이 그대로 보인다. 통째로 저장하면 옛날 내용이 남는다 |
| 순서 | 최근에 저장한 것을 앞에 넣는다 |
| 저장하지 않는 것 | 빈칸에 입력한 값(이름, 생년월일 등). 개인정보이고, PRD에서 "내 정보 기억하기"는 나중에 하기로 했다 |

## 사용자 흐름

### 흐름 ① 인스타 링크로 들어온 사람 (가장 많을 것)

| 순서 | 사용자가 하는 일 | 쓰는 데이터 |
|---|---|---|
| 1 | 인스타 릴스에서 프로필 링크를 누른다 | |
| 2 | 프롬프트 상세가 열린다 (홈을 거치지 않음) | `id` |
| 3 | 결과 예시를 보고 "이렇게 바뀌는구나" 확인한다 (사진 프롬프트는 전 → 후) | `images`, `beforeImage` |
| 4 | (빈칸이 있으면) 빈칸을 채운다 | `blanks` |
| 5 | 이용 방법을 확인한다 (어느 AI에, 사진이 필요한지) | `ai`, `needsPhoto` |
| 6 | 복사 버튼을 누른다 | `promptText` |
| | └ 빈칸이 비어 있으면: 복사하지 않고 "OO을 입력해 주세요" + 그 칸으로 커서 이동 | `blanks`의 `label` |
| | └ 성공하면: "복사했어요" 토스트 | |
| 7 | AI로 바로가기를 누른다 → AI가 새 탭에서 열린다 | `ai` |
| 8 | (사진이 필요하면) AI 채팅창에 내 사진을 첨부한다 | `needsPhoto` |
| 9 | 붙여넣고 보낸다 → **결과를 받는다** ★ | |
| 10 | (마음에 들면) 우리 탭으로 돌아와 저장을 누른다 → 화면은 그대로, "저장했어요" 토스트 | `id` → localStorage |

### 흐름 ② 홈으로 들어온 사람

| 순서 | 사용자가 하는 일 | 쓰는 데이터 |
|---|---|---|
| 1 | 홈에서 카드 줄을 둘러본다 (또는 주제 칩을 눌러 그 주제만 본다) | `topic`, 홈의 인기 id 목록 |
| 2 | 마음에 드는 카드를 누른다 | `id` |
| 3 | 프롬프트 상세가 열린다 | |
| → | 이후는 **흐름 ①의 3번부터 같다** | |

### 알림 방식

복사와 저장 알림은 모두 **토스트**(잠깐 떴다가 알아서 사라지는 알림)로 한다. 모달은 닫기를 눌러야 해서 하던 일을 끊는다. 알려 주기만 하면 되는 일에 앞을 막지 않는다 (PRD "첫 화면 이벤트 모달 ❌"과 같은 이유).
