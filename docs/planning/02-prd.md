# PRD: 무엇을 만드는가

- 작성일: 2026-11-24
- 단계: P1 기획 — PRD (Product Requirements Document, 제품 요구사항 문서)
- 이전 문서: [P0 서비스 정의](01-p0.md)

> P0가 "누구를 위해, 왜"였다면 PRD는 "**무엇이 있어야 하는가**"다.
> 어떻게 만드는지(코드)와 어디에 두는지(화면 구조)는 여기서 정하지 않는다.

## 목적

인스타에서 재미 프롬프트를 보고 온 라이트 사용자가 **DM 없이 바로 복사하고, 저장해서 다시 찾게** 한다. (자세한 내용은 P0)

## 사용자 이야기

형식: `[누구]로서, [무엇]을 하고 싶다. 왜냐하면 [이유]`

### A. 릴스 링크로 들어온 사람 (가장 많을 것)

크리에이터가 "프롬프트는 프로필 링크에"라고 건 링크로 **홈이 아니라 프롬프트 상세 페이지에 바로** 들어온다.

1. 릴스를 보고 온 사람으로서, **결과 예시 이미지**를 먼저 보고 싶다. 왜냐하면 내가 원하던 그 결과인지 확인하고 싶으니까.
2. 로그인하지 않은 사람으로서, **버튼 하나로 바로 복사**하고 싶다. 왜냐하면 DM을 기다리지 않으려고 여기 왔으니까.
3. 프롬프트에 내 정보가 필요하면, **빈칸만 채워서** 완성된 프롬프트를 복사하고 싶다. 왜냐하면 긴 글을 직접 고치기 어려우니까.
4. AI를 자주 안 써본 사람으로서, **어느 AI에 어떻게 붙여넣는지** 알고 싶다. 왜냐하면 처음 해보면 헷갈리니까.
5. 복사한 뒤 **그 AI로 바로 가고** 싶다. 왜냐하면 앱을 직접 찾아 여는 게 번거로우니까.
6. 결과가 재밌으면 **친구에게 공유**하고 싶다. 왜냐하면 같이 해보고 싶으니까.
7. 마음에 들면 **저장**하고 싶다. 왜냐하면 나중에 다시 쓰고 싶으니까. → 이때 로그인한다.

### B. 홈으로 들어온 사람

1. 무엇을 할지 정하지 않은 사람으로서, **주제(연애·사주·셀피 등)를 눌러 구경**하고 싶다. 왜냐하면 검색어가 떠오르지 않으니까.
2. 요즘 **인기 있는 프롬프트**를 보고 싶다. 왜냐하면 남들이 많이 하는 게 궁금하니까.
3. 원하는 게 분명하면 **검색**하고 싶다.

### C. 저장해 두고 다시 온 사람

1. 저장한 사람으로서, 저장한 프롬프트를 **주제별로 나뉜 채로** 보고 싶다. 왜냐하면 폴더를 직접 만들기 귀찮으니까.
2. 저장한 프롬프트를 **보관함에서 바로 다시 복사**하고 싶다. 왜냐하면 다시 쓰려고 저장했으니까.
3. 이제 안 쓰는 프롬프트는 **지우고** 싶다.

## 기능 목록

### 1. 프롬프트 상세

| 기능 | 내용 |
|---|---|
| 결과 예시 | 이 프롬프트로 만든 결과 이미지(또는 글) |
| 복사 | 버튼 하나로 복사. **로그인 없이** 된다 |
| 빈칸 채우기 | 프롬프트에 `[이름]`, `[생년월일]` 같은 빈칸이 있으면 입력칸을 보여주고, 채운 내용으로 완성된 프롬프트를 복사한다 |
| 이용 방법 | 어느 AI에 붙여넣는지, 순서 안내 ("복사 → AI에 붙여넣기 → 결과 확인") |
| AI로 바로가기 | 복사 후 해당 AI 사이트를 연다 |
| 공유 | 모바일은 휴대폰 기본 공유창, PC는 링크 복사 |
| 저장 | 보관함에 저장. 이때 로그인을 요청한다 |
| 출처 | 만든 크리에이터 표시 (P0 원칙) |
| 관련 프롬프트 | 비슷한 주제의 다른 프롬프트 |

### 2. 홈

| 기능 | 내용 |
|---|---|
| 주제 칩 | 연애 · 사주 · 셀피 등 주제를 아이콘/태그 칩으로 **항상 보이게** 둔다. 누르면 그 주제만 보인다 |
| 카드 줄 | 넷플릭스처럼 가로 카드 줄. 출시 때는 **2~3줄** (예: 인기 TOP, 주제별) |
| 사용법 한 줄 | "복사 → AI에 붙여넣기 → 결과 확인" 3단계를 짧게 |

### 3. 검색

| 기능 | 내용 |
|---|---|
| 검색 | 헤더의 🔍 아이콘을 누르면 검색창이 열린다 |

### 4. 보관함

| 기능 | 내용 |
|---|---|
| 목록 | 저장한 프롬프트를 **주제 태그로 자동 분류**해서 보여준다 (폴더를 직접 만들지 않음) |
| 바로 복사 | 보관함 카드에서 바로 복사. 빈칸이 있는 프롬프트는 "채우고 복사" → 상세로 이동 |
| 지우기 | 저장 취소 |

### 5. 로그인

| 기능 | 내용 |
|---|---|
| 소셜 로그인 | 카카오 · 구글. **저장할 때만** 필요하다. 구경과 복사는 로그인 없이 된다 |

## 하지 않기로 한 것과 이유

| 아이디어 | 결정 | 이유 |
|---|---|---|
| 로그인해야 복사 | ❌ | P0에서 푼 문제가 "팔로우·댓글·DM을 거쳐야 받는다"였다. 로그인 벽은 같은 문제를 다시 만든다 |
| 첫 화면 이벤트 모달 | ❌ | 사람들은 내용도 안 보고 닫는다. 릴스 링크로 온 사람의 앞을 막는다. 이벤트가 생기면 상단 배너 한 줄로 |
| 스크롤 스토리형 메인 + 마지막 CTA | ❌ | 처음 보는 제품을 설득하는 랜딩 페이지 방식이다. 사용자는 이미 원하는 걸 알고 오므로 콘텐츠를 먼저 보여준다 |
| 필터 버튼을 전부 펼쳐 두기 | ❌ | 선택지가 많으면 라이트 사용자는 고르다 지친다 (OpenPrompt 분석). 주제 칩 + 검색 아이콘으로 충분하다 |
| 카드 줄 10개 이상 | ❌ (출시 때) | 출시 때 프롬프트는 30개다. 줄이 많으면 같은 카드가 반복돼 비어 보인다 |

## 나중에 할 것 (출시 후)

- **AI 캐릭터와 대화하며 프롬프트 완성**: AI API(유료 외부 서비스), 백엔드, API 키 보안이 필요하다. 출시 전에는 "빈칸 채우기"로 대신한다
- **보관함 메모**: 있으면 좋지만 핵심은 아니다. "누구에게 받았나"는 출처 표시가 해결한다
- **내 정보 저장해서 빈칸 자동 채우기**: 생년월일 같은 개인정보라 서버 저장은 부담이 크다. 한다면 "이 기기에만 기억하기"부터
- **카카오 공유 카드**: 카카오 개발 도구가 따로 필요하다
- **이벤트 배너**
