# ADR 001: TypeScript는 출시 후에 도입한다

- 날짜: 2026-11-20
- 상태: 채택

## 맥락

- Promnive는 1인 개발 프로젝트이고, 2027-01-29 정식 출시가 목표다.
- 개발자(나)는 JavaScript와 React를 배우면서 만드는 단계다. 구조분해, state, useEffect 같은 기초를 아직 다지는 중이다.
- 실무에서는 TypeScript가 사실상 표준이라, 언젠가는 도입해야 한다.
- 지금 TypeScript를 함께 쓰면 "JS 문법 + React 동작 + 타입 오류"를 동시에 해결해야 한다. 막히는 지점이 늘어나 출시 일정을 지키기 어렵다.

## 결정

- **출시(1/29)까지는 JavaScript로 개발한다.**
- **출시 후 2월에 "JS → TS 마이그레이션" 스프린트**를 따로 잡아 TypeScript로 옮긴다.

## 결과

**좋아지는 점**

- 한 번에 배울 것이 줄어서, JS · React 기초에 집중할 수 있다.
- 출시 일정의 위험이 줄어든다.
- 마이그레이션을 직접 해보면서 "타입이 없을 때 무엇이 불편했는지"를 체감하고 TypeScript를 배울 수 있다.

**감수하는 점**

- 출시 전까지는 타입 검사가 없어서, 오타나 잘못된 값이 실행해 봐야 드러난다.
  → ESLint와 브라우저 DevTools 확인으로 보완한다.
- 출시 후 마이그레이션 작업이 추가로 생긴다.

## 검토한 다른 방법

| 방법 | 고르지 않은 이유 |
|---|---|
| 처음부터 TypeScript | 학습 부담이 커서 출시 일정 위험이 가장 크다 |
| JS + JSDoc 주석으로 타입 검사 | 결국 타입 문법을 따로 배워야 해서, 부담은 비슷하고 얻는 건 적다 |
